# 剪贴板记录备注设计

## 基线和范围

- 实现基线：GitHub `origin/master` 的 `d36e75d`（v1.1.13 更新清单提交）。
- 交付形态：真实 Windows 桌面应用内的可交互原型；编译、测试和本机运行验证后停止，不创建安装包、不发布 GitHub Release。
- 保留：现有待办工作区、折叠胶囊、笔记、图片粘贴和笔记缩放功能不改动。

## 用户流程

1. 用户在主面板的任意剪贴板记录上右键，打开既有的完整内容预览窗口。
2. 预览窗口保留当前的内容编辑或显示名称编辑区，并在其下新增独立的“备注”单行输入框。
3. 备注接受 0 到 100 个字符；输入会去除首尾空白，不允许换行。清空后保存即删除备注。
4. 点击保存或使用 Ctrl+S 时，内容变更和备注变更作为同一笔记录更新写入加密历史。
5. 成功保存后，无需重启，主面板对应记录的小字刷新为：
   - 无备注：`置顶（可选） · 相对时间 · 原有详情`
   - 有备注：`置顶（可选） · 备注 · 相对时间 · 原有详情`
6. 辅助行始终单行省略；完整备注可由卡片原生 `title` 提示读取。
7. 搜索同时匹配正文、原有详情、原始路径、显示名称和备注。

## 数据与兼容性

`ClipboardRecord` 在末尾新增可空的 `Remark` 字段。末尾可选字段使旧版本写出的 JSON 在反序列化时自然得到 `null`，不触发历史隔离或清空。

`PreviewEdit` 增加备注值，并由 `ClipboardRecordEditor` 统一执行验证和规范化。内容不合法时维持现有失败语义，备注不会被部分保存。

去重捕获同一条剪贴板内容时，`JsonClipboardHistorySource.UpsertAsync` 必须保留已存记录的备注。这保证反复复制同一内容不会抹除用户标注；新的复制时间和来源元数据仍按当前行为刷新。

## 真实 UI 和桥接

`ContentPreviewWindow` 向真实 `product-shell.html?surface=preview` 状态消息中发送备注，并在保存消息中接收备注。`WebBridgeRequest` 增加一个独立字段，不把备注拼入正文。

预览 Web UI 在当前编辑区域下添加一个和现有玻璃主题一致的 `备注` 输入区、字符计数和清空图标按钮。它属于现有可移动、可缩放的预览窗口，不新增窗口，也不改变置顶、自动隐藏、关闭和未保存确认行为。未保存判断须同时比较内容和备注。

`CursorPanelWindow.BuildShellState` 单独发送 `remark`，而不是污染当前 `meta` 数据。主面板 `recordMetadata` 按既有顺序组合置顶、备注、原 `meta` 和字符计数，从而不覆盖图片尺寸、文件路径、来源程序或相对时间。

## 失败处理

- 备注超过 100 字或含换行：预览窗口保留草稿并展示明确错误，历史不写入。
- 记录已删除或记录类型已在其他操作中变化：沿用现有“记录已更新，请重新打开预览后再保存”恢复路径。
- 历史文件损坏、加密或原子写入失败：沿用现有 JSON 历史隔离和失败反馈；不引入第二套备注存储。

## 验证

- Core 单元测试：备注的验证、清空、文本/链接/图片/文件编辑、链接转文本和字段保留。
- 历史测试：旧 JSON 缺少 `Remark` 可读；保存后重载仍有备注；同内容再次复制时备注保留。
- 视图模型测试：按备注搜索；保存后列表记录在原位置刷新。
- Web/UI 契约测试：预览状态和保存消息包含备注，列表辅助行顺序正确且无备注时没有多余分隔符。
- 本机运行：从主面板右键进入真实预览，新增、修改、清空备注，重启应用并验证备注仍在；检查待办入口、待办排序、折叠胶囊和笔记仍可用。

## 不在本阶段

- 多行备注、富文本、备注图片、备注单独排序或筛选页。
- 云同步、跨设备同步、安装包和发布。
