# 花海剪贴板大量历史性能修复设计

## 目标

在不改变现有视觉、数据格式和用户操作方式的前提下，使 1000 条剪贴板历史仍能流畅打开、滚动、搜索和操作，并保持点击复制后面板立即隐藏。

## 已确认基线

- 点击复制的独立卡顿源是系统剪贴板写入曾同步占用 UI 线程；候选修复已将写入移到专用 STA 后台线程，并先隐藏面板。
- 历史列表当前在每次状态更新时通过 `innerHTML` 重建全部卡片，再为每一行重新绑定复制、置顶、收藏和删除事件。
- 同一正式 `product-shell.html` 的匿名数据测试结果：100 条 P50 18.1ms / P95 82.0ms，500 条 P50 48.3ms / P95 58.1ms，1000 条 P50 87.8ms / P95 101.3ms。
- 当前正式安装版位于 `F:\HuahaiClipboard`；性能测试必须使用隔离数据目录，不读取、覆盖或提交用户历史。

## 选定方案

采用虚拟列表与事件委托。

所有历史仍保存在现有内存数组中，搜索、筛选、排序、置顶和收藏继续针对完整数据集执行。DOM 只生成滚动视口附近的记录，通过上下占位空间保持原有滚动高度和滚动条语义。列表容器只注册一组委托事件，根据行的记录 ID 路由复制、置顶、收藏和删除操作。

第一阶段保持原生端现有完整状态消息不变，以避免同时修改跨 WebView 协议。完成虚拟列表后重新测量；只有当 1000 条状态传输仍超过性能目标时，第二阶段才增加增量消息。第二阶段属于条件性优化，不是第一阶段完成的前提。

## 组件边界

### 虚拟窗口计算模块

新增独立的纯 JavaScript 模块，输入总条数、滚动位置、视口高度、单行高度和预渲染数量，输出开始索引、结束索引、顶部占位高度和底部占位高度。模块不访问 DOM，使用 Node 测试覆盖边界、快速滚动和空列表。

### 列表渲染适配器

正式 UI 母版继续拥有卡片 HTML、图标和材质。适配器调用虚拟窗口模块，只渲染可见切片，并在滚动时通过 `requestAnimationFrame` 合并高频更新。搜索、筛选、排序或完整状态变化后重新计算窗口，但不会生成全部 DOM 行。

### 事件委托

记录列表容器统一处理点击事件。操作按钮仍保留原有类名、标题、状态颜色和可访问名称；缩略图请求仍只针对已经进入可见窗口的图片行执行。

## 行为与兼容性

- 保持当前排序：置顶优先，其余按既有顺序。
- 搜索和类型筛选覆盖全部历史，而不是只搜索已渲染行。
- 置顶、收藏、删除后立即反映结果，并尽量保持当前滚动位置。
- 复制普通行时立即隐藏面板；后台写入失败时恢复面板并显示错误提示。
- 保留当前 DOM 控件标识、主题、字体、液态玻璃、缩略图、键盘与鼠标操作合同。
- 不修改历史文件结构、安装位置、更新机制、隐私排除规则或用户数据。

## 性能与正确性验收

- 匿名 100、500、1000 条数据均可完整搜索、筛选和操作。
- 1000 条时实际 `.record` DOM 数量不超过 80。
- 1000 条状态应用与可见绘制的 P95 不超过 50ms；不存在超过 50ms 的同步列表重建长任务。
- 从顶部连续滚动到底部至少采样 20 个位置：索引单调、无空白窗口、无重复 ID、无明显跳回。
- 快速滚动期间每个动画帧最多执行一次渲染提交。
- 置顶、收藏、删除、缩略图请求和复制分别通过可见行与滚动后行验证。
- 点击复制后面板隐藏不等待系统剪贴板写入；失败恢复路径通过自动化测试验证。
- 候选版使用隔离数据目录；测试结束恢复 `F:\HuahaiClipboard\HuahaiClipboard.App.exe --background`。

## 回滚与停止条件

虚拟列表作为单独功能检查点提交，可独立回滚而不影响此前的剪贴板异步写入和启动器修复。如果固定行高无法保持现有卡片布局，或虚拟化导致滚动、缩略图、焦点或操作回归，则停止加入原生增量协议，先恢复全量列表并保留性能红灯证据重新设计。

第一阶段达标后不自动扩大到数据库、分页、框架替换或 UI 重做。
