# 花海剪贴板主动更新提醒设计

## 目标

当维护者发布新的 GitHub Release 后，正在后台运行的旧版花海剪贴板应自动发现新版并主动提醒用户。用户无需进入设置页或点击“检查更新”，但安装仍由用户确认，不进行静默强制更新。

## 用户端条件

- Windows 10 或 Windows 11 x64。
- 花海剪贴板正在运行，包括隐藏到托盘的后台状态。
- “启动时自动检查更新”开关保持开启；默认开启。
- 本机网络能够通过 HTTPS 访问 `github.com` 和 `api.github.com`。
- 不需要 GitHub 账号、登录、管理员权限或额外后台服务。
- Windows 通知若被关闭，不影响检查更新；托盘状态、主面板红点和设置页状态仍作为降级提醒。

维护者必须创建正式 GitHub Release，并上传固定名称 `HuahaiClipboard-Setup.exe`。普通 Git 提交不视为可安装版本。

## 已确认根因

现有程序会在 WebView 就绪后执行一次更新检查，但检查结果只发送给“关于与更新”页面的 `updateStatus` 区域。该页面未打开时，用户看不到任何提示；程序也没有调用托盘气泡、Windows 通知或主面板徽标。因此问题不是未检测到新版，而是检测结果没有进入可见通知通道。

## 行为设计

1. 程序启动且 UI 载体就绪后立即检查一次。
2. 后台运行期间每 5 分钟检查一次最新 GitHub Release。
3. 使用 GitHub 的 `ETag`/条件请求；返回未变化时不重复解析或提醒。
4. 检测到高于当前版本的正式 Release 后：
   - 显示托盘气泡通知，内容包含新版本号；
   - 主面板设置按钮显示红色更新圆点；
   - 主面板下次唤出时显示一次“发现新版本”提示；
   - “关于与更新”页面继续显示完整状态和“立即更新”按钮。
5. 用户可选择：
   - “立即更新”：沿用现有下载、大小、SHA-256/固定发布证书校验和安装流程；
   - “稍后提醒”：本版本 24 小时内不再弹气泡，但红点保留；
   - “查看更新内容”：打开对应 GitHub Release 页面。
6. 同一版本每次程序运行最多主动弹出一次；关闭通知不会被高频打扰。
7. 用户安装成功或当前版本已不低于远端版本后，更新红点和待提醒状态清除。

## 组件边界

### ProactiveUpdateCoordinator

负责启动检查、5 分钟周期、并发去重、失败退避和生命周期取消。它只调度检查，不负责网络解析或 UI。

### GitHubUpdateCheckService

继续负责 Release 获取、版本比较和安装包元数据验证。新增条件请求缓存支持，保留 API 限流时的 Release 页面降级路径。

### UpdateNotificationService

负责托盘气泡通知和用户动作。优先复用现有托盘基础设施，不引入常驻进程或新的重量级依赖。

### WebView 更新状态桥

继续发送 `updateStatus`，并增加可持久显示的“更新可用”状态，使主面板红点、一次性提示和设置页状态共享同一来源。

### 本地提醒状态

仅保存以下非敏感数据：最后已提醒版本、稍后提醒截止时间和可选 ETag。数据仍位于安装目录下当前 Windows 用户的 `Data` 子目录，不上传到 GitHub。

## 失败与降级

- 首次失败后 15 分钟重试；连续失败后延长到 60 分钟，成功后恢复 5 分钟周期。
- GitHub API 返回 403/429 时使用现有 Release 页面降级检查，不向用户显示频繁错误。
- 完全离线时静默保留当前版本，不影响剪贴板、快捷唤出或后台运行。
- Windows 通知被关闭时，托盘菜单更新标记、主面板红点和设置页状态继续可见。
- 下载或签名校验失败时不替换旧版本，并显示明确错误。

## 隐私与性能

- 只请求公开 GitHub Release 元数据，不上传剪贴板内容、图片、设置、排除列表或账号信息。
- 条件请求和单实例定时器避免重复网络访问。
- 检查在后台异步执行，不阻塞剪贴板监听、面板唤出或 UI 线程。
- 不新增常驻服务器连接；空闲内存目标基本不变。

## 验收

- 从当前版本指向更高测试版本时，启动检查无需打开设置页即可产生托盘提醒和主面板红点。
- 后台运行 5 分钟后会再次检查；同一时刻不会并发发起多个请求。
- 同一版本每次运行只主动弹出一次，选择“稍后提醒”后 24 小时内不重复弹出。
- 关闭 Windows 通知后仍能通过红点和设置页发现更新。
- API 403/429、离线、无新版本和安装包元数据异常均有确定的降级行为。
- 现有手动检查、立即更新、固定发布者签名验证和本地数据保护测试继续通过。
