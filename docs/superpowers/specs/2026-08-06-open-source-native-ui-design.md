# 花海剪贴板开源原生 UI 迁移设计

日期：2026-08-06  
状态：用户已确认产品方向、UI 保留范围、运行流程与性能验收标准

## 1. 目标

在不改变“花海剪贴板”现有视觉设计、核心功能和本机数据格式的前提下，将正式 Windows 客户端从 WinUI 3 + WebView2 宿主迁移为开源友好的 WPF 原生界面，以实现：

- 面板隐藏、后台待机时内存中心目标约 50MB；验收区间为 40–70MB。
- 不运行 WebView2、Chromium 或其他浏览器渲染子进程。
- 面板在后台预先创建，唤出时不加载网页引擎，热唤出目标 50ms 内。
- 滚动、液态反光、樱花与按钮反馈在测试机上保持接近 60FPS。
- 浏览器中仍能打开完整、可交互的网页原型，继续用于未来 UI 迭代。
- 项目保持开源，应用界面不加入第三方引擎归属链接或广告。

## 2. 明确不采用的方向

- 不采用 Sciter。用户不接受其 Engine EULA 要求在应用“关于”页面加入归属链接。
- 不采用 Ultralight 或其他闭源、付费或要求产品内署名的渲染引擎。
- 不采用 Servo、Blitz 等当前仍处于原型或实验阶段、无法稳定覆盖现有交互能力的开源网页引擎。
- 不继续以 WebView2 作为正式 UI 渲染器；暂停或回收工作集不能同时保证约 50MB 和无冷启动卡顿。
- 不重新设计一套新的视觉界面，不把截图当作正式界面，不交付只有外观而没有真实操作的控件。

## 3. 唯一视觉母版

当前已批准的 `src/HuahaiClipboard.App/Assets/Web/product-shell.html` 及视觉源版本 1.0.4 是迁移基线。原生版是该基线的派生实现，不是重新创作。

必须保留：

- 狐狸图标与“花海剪贴板”艺术字。
- 当前信息层级、面板布局、列表卡片和完整设置页。
- 玫瑰紫液态玻璃及另外四套主题。
- 全透明拟态玻璃边缘，不增加白框、黑框或原生标题栏。
- 背景层小花瓣飘落，默认低强度并可关闭。
- A + E 点击动效、按钮反光、钉子置顶、收藏和删除图标。
- 当前字体比例、文字对比度、缩放行为和多显示器位置记忆。

不同渲染器允许出现字体抗锯齿级别的微小像素差异，但布局、尺寸、颜色、圆角、图标、透明度和动效语义不得自行变化。

## 4. 架构

### 4.1 正式客户端

正式客户端继续使用 .NET 8 和现有 C# 业务层：

```text
Windows 剪贴板、托盘、快捷键
            ↓
HuahaiClipboard.Core（保留）
            ↓
PanelViewModel / SettingsViewModel（保留）
            ↓
WPF 原生面板（新宿主）
```

WPF 采用 MIT 许可，不要求在应用界面展示归属链接。WPF 负责窗口、布局、控件、键盘焦点、列表虚拟化和无障碍基础；Windows DWM/WPF 合成层负责透明背景、阴影、圆角和动画。只有在 WPF 样机无法通过性能门槛时，才允许把玻璃或高频动效层局部升级为 Direct2D/DirectComposition；不得未经门槛证据把整个项目扩写为自研渲染器。

### 4.2 共同 UI 规范

新增版本化 `ui-spec.json`，作为网页原型与原生界面的共同设计合同，而不是再维护两套随意变化的常量。至少包含：

- `schemaVersion` 与视觉母版版本。
- 五套主题、文字颜色、玻璃颜色和透明度范围。
- 面板、设置页、列表行、图标、间距、圆角和缩放参数。
- 字体族、字号、字重和艺术字资源。
- 花瓣、反光、按钮与点击反馈的触发、时长、缓动和降级动效。
- 页面、控件 ID、可访问名称、可见状态和交互结果。
- Windows 10/11 与 100%、150%、200% DPI 夹具。

生成步骤输出 Web CSS 变量和 C# WPF 资源。生成物不得成为新的手工编辑源；所有共享参数必须回写到 `ui-spec.json`。

### 4.3 网页原型

浏览器原型继续可独立打开，并使用 `browser-adapter` 提供固定模拟数据、设置持久化和可见反馈。原型中的每个可点击控件必须执行模拟动作，或明确显示“仅正式版可用”的禁用原因。

正式客户端使用相同控件 ID 和交互合同连接真实 ViewModel。网页不直接写入正式剪贴板历史，正式客户端不加载 `localhost` 或在线页面。

## 5. 运行与数据流

- 程序启动后创建原生面板并隐藏，同时启动托盘、剪贴板监听和全局输入监听。
- 右键双击、自定义键盘或鼠标快捷键、托盘菜单均调用同一唤出入口。
- 唤出入口刷新 ViewModel、定位到指针所在显示器、设置 Topmost、显示窗口并聚焦搜索框。
- 单击记录完成真实复制后立即隐藏；隐藏前取消 Topmost。
- 置顶、收藏、删除、自动清理、主题、透明度、花瓣、缩放、排除应用与开机自启继续使用现有 Core 服务。
- 历史、设置、图片缓存和窗口位置的本机文件路径及格式保持兼容；迁移不触发数据清空或强制迁移。
- 密码管理器、无痕窗口和用户排除应用的隐私规则保持不变。

## 6. 错误处理与恢复

- UI 资源或 `ui-spec.json` 版本不匹配时，构建门禁失败，不生成安装包。
- 面板渲染失败不得结束后台进程；托盘保留“重新打开”和“退出”，并展示可理解的本机错误提示。
- 单条剪贴板记录损坏不得阻断整个列表；保留现有恢复提示和可删除路径。
- 设置保存失败时恢复到最后一次已持久化值，不展示虚假的成功状态。
- 全局快捷键注册失败时，右键双击和托盘入口仍可使用，并在设置中显示冲突原因。
- 不上传崩溃日志、剪贴板内容或设置；首版继续完全本机运行。

## 7. 性能验收

原生样机必须先通过以下门槛，才允许替换正式宿主：

- 隐藏并稳定 60 秒后，以任务管理器口径的 Private Working Set 连续采样三次，中心目标约 50MB，允许区间 40–70MB。
- 无 WebView2、Chromium、Servo、Sciter 或其他 UI 渲染子进程。
- 预创建窗口热唤出 30 次，P95 小于或等于 50ms。
- 使用 1,000 条固定记录验证列表虚拟化、筛选、搜索和行内按钮；滚动目标不低于 55FPS，输入和按钮反馈无肉眼可见停顿。
- 花瓣低强度、液态反光和 A + E 点击动效同时开启时不阻塞复制与隐藏。
- Windows 10、Windows 11，以及 100%、150%、200% DPI 下分别验证尺寸、命中区域、圆角和文字清晰度。

若样机内存超过 70MB或关键交互无法达到目标：

1. 先定位占用与掉帧来源；
2. 只优化被证实的瓶颈；
3. 仍不达标则停止迁移，不替换当前正式版本；
4. 由用户决定是否接受局部 Direct2D 升级或调整指标。

不得通过强制裁剪工作集、隐藏进程统计、降低文字质量或移除已批准动效伪造达标结果。

## 8. 视觉与交互验收

- 固定相同窗口尺寸、主题、数据、语言和 DPI，分别采集网页母版与原生版截图。
- 检查主面板、完整设置页、五套主题、列表滚动状态、空状态、错误提示和关键动效帧。
- 生成前图、后图和差异图；几何偏差原则上不超过 1 个逻辑像素，字体抗锯齿差异单独标记。
- 使用 Windows 原生 UI 自动化验证搜索、过滤、滚动、复制、置顶、收藏、删除、设置、缩放、拖动、关闭、托盘和快捷键。
- 所有可见控件必须真实工作、明确禁用并解释原因，或从正式界面移除。
- 原生可交互版本必须交给用户体验确认；未经确认不得替换当前安装包。

## 9. 测试范围

- 保留并运行现有 Core 单元测试和本机存储测试。
- 为 `ui-spec.json` 生成器、版本兼容和控件合同增加确定性测试。
- 为 1,000 条数据、主题/DPI 组合和错误状态建立固定测试夹具。
- 为后台内存、唤出延迟、滚动帧率和动画帧率建立可重复性能探针。
- 为 Windows 10/11 运行启动、后台、置顶、隐藏、托盘、快捷键、开机自启和卸载回归。
- 安装器必须继续允许用户选择非 C 盘位置，卸载时保留用户数据的现有策略不变。

## 10. 迁移与回退边界

- 当前 WebView2 正式版本保持可运行，原生样机在隔离路径开发。
- 第一检查点只包含共同 UI 规范、生成器和原生主面板样机，不修改安装器。
- 性能与视觉门槛通过后，才迁移设置页和完整真实适配器。
- 完整交互、安装和卸载验证通过且用户批准后，才允许切换正式入口并生成新安装包。
- 任何阶段失败都保留当前版本和本机数据；不使用破坏性 Git 回退，不覆盖用户未提交文件。

## 11. 非目标

- 不增加登录、云同步、遥测、在线账户或跨设备同步。
- 不在本阶段新增剪贴板功能、主题或设置项。
- 不修改清理、收藏、置顶、隐私排除和快捷键的产品语义。
- 不承诺在所有电脑上固定显示单一内存数字；以约定机器、口径和采样方法验收。

## 12. 完成定义

只有同时满足以下条件，原生 UI 迁移才算完成：

1. 后台内存、热唤出和帧率门槛通过；
2. 网页母版与原生版视觉对比通过；
3. 所有批准控件的真实交互通过；
4. 现有数据、隐私、快捷键、托盘、启动和卸载行为通过；
5. 用户亲自体验原生可交互版本并确认；
6. 新安装包通过 Windows 10/11 安装、启动和卸载验证。
