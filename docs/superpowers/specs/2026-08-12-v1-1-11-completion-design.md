# 花海剪贴板 v1.1.11 完整性修复设计

## 目标

在不改变已确认 WebView 液态玻璃 UI、不迁移或上传用户数据、不替用户安装的前提下，补齐 v1.1.10 审计发现的正式功能缺口并发布可手动更新的 v1.1.11。

## 已确认行为

- 点击已有记录会在成功写入系统剪贴板后更新为最近使用；记录 ID、收藏和置顶状态保持不变，不产生重复记录。
- 置顶记录只在置顶区按最近使用时间排序，普通记录只在普通区上浮。
- 按条数自动清理可开关，上限为 1–10000 条普通记录；默认关闭、默认值 100。超出时删除最早普通记录，收藏和置顶不计入上限。
- 时间清理保留 3、7、30 天三个选项，并与条数清理同时生效；启动、复制、设置变更和后台周期检查均应用规则。
- 删除、时间清理、条数清理、1000 条保护和两种清空操作都同步删除已无记录引用的加密图片文件；启动时清理历史遗留孤儿图片。
- 点击面板外是自动隐藏，不是自动删除；开关继续放在“设置 → 系统”，默认开启。
- 正式版复制且未开启自动隐藏时提供复制动效和成功提示；开启时继续立即隐藏。
- 自定义输入扩展常用键盘、数字键盘、媒体键、滚轮和鼠标侧键；裸左键和裸右键会破坏系统基本操作，因此不允许，界面给出可读原因。右键双击继续默认启用并可与自定义方式并存。
- 面板缩放继续支持 80%–160%、1% 精度、预览/提交分离；预览期间保持圆角裁剪。拖动按显示帧合并位置更新，避免 8ms UI 定时器争抢 WebView 渲染。
- GitHub API 没有提供合法 SHA-256 时，只显示版本和 Release 链接，不允许自动下载；自动安装必须依次通过 HTTPS 元数据、大小、SHA-256 和固定发布者签名。
- Git 提交本身不触发客户端更新；只有更高版本号且包含 `HuahaiClipboard-Setup.exe` 的公开 GitHub Release 才触发更新提醒。

## 结构

- `JsonClipboardHistorySource` 继续作为历史记录唯一写入点，在同一串行锁内确定被移除记录，保存历史后删除对应图片，避免各个 UI 调用方重复清理。
- `ProtectedClipboardImageStore` 增加受目录边界保护的删除和孤儿回收能力。
- `ClipboardRetentionService` 统一执行时间与条数规则，供捕获、启动、设置和周期检查复用。
- Web 设置沿用正式 `product-shell.html` 的存储页和现有玻璃进度条视觉，不创建第二套页面。
- 更新器继续使用现有 GitHub Release 和安装器签名链，只收紧缺失摘要时的行为。

## 错误与恢复

- 剪贴板写入失败时不更新最近使用时间，也不隐藏已选择“保持显示”的面板。
- 历史先原子保存，再删除不再引用的图片；图片删除失败不会恢复已删除历史，下一次启动孤儿回收会重试。
- 非法条数设置不保存，保留上一次有效值并显示错误。
- 更新缺少 SHA-256 时保留“在 GitHub 查看”路径，不进入下载和安装阶段。

## 验证

- Core 单元测试覆盖上浮、条数清理、受保护记录、全部历史变更对应图片回收和更新摘要门槛。
- Web 测试覆盖正式设置入口、原风格进度条、1–10000 校验、复制反馈、交互合同与快捷输入。
- Windows 集成测试覆盖图片/文件真实剪贴板格式与本机写入防重复。
- 构建后运行正式 UI、安装器、隐私、版本、依赖和发布合同测试；发布资产计算 SHA-256 并核对 GitHub digest。

## 自检

本文没有占位项。数据目录继续固定为安装目录下 `Data/<SID>`；安装位置继续禁止 C 盘；发布不包含用户数据；本轮不自动安装到用户电脑。
