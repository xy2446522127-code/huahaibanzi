# 花海剪贴板：主面板更新通知条与缩小图标设计

## 目标

当后台检查发现更高版本的正式 GitHub Release 时，用户无需进入“设置 → 关于与更新”即可在主面板看到明确提醒；同时增大并更换缩小按钮图标。改动必须沿用已确认的液态玻璃界面，不遮挡剪贴记录，不影响面板唤出、复制、拖动和缩放性能。

## 已确认的视觉方案

### 更新提醒：方案 B

- 设置齿轮右上角显示立体红色更新圆点，直到用户成功安装新版本或当前版本不低于远端版本。
- 下一次唤出主面板时，在搜索栏下方、分类筛选栏上方显示一条液态玻璃更新通知条。
- 通知条不使用左侧图标，内容从左边距直接开始。
- 通知条采用三列布局：可收缩的文字区、固定宽度“稍后”按钮、固定宽度“更新”按钮。任何 80%–160% 面板缩放比例下，文字不得进入按钮区域；空间不足时文字以省略号收尾。
- 玻璃底色提高透明度，保留背景透出、18px 模糊、轻微饱和度、顶部细反光和边缘描线。文字保持不透明并增加轻微暗色投影，不随玻璃透明度一起变淡。
- 主标题为“发现新版本 v{版本号}”，副标题为“已完成安全检查，可选择更新”。
- 通知条进入动效只执行一次，使用短距离淡入；启用“减少动效”时立即显示，不播放位移动画。

### 缩小按钮：方案 A

- 保留现有按钮尺寸、圆角、玻璃材质和位置，只替换内部图标。
- 图标改为 23px 宽的圆头粗横线，视觉居中，线宽约 2.8px。
- 按钮含义仍为“隐藏到后台”，不是退出程序；单击后立即隐藏，剪贴板监听和托盘进程继续运行。
- 按钮仍属于交互控件区域，不触发面板拖动。

## 交互行为

1. 程序启动并完成 UI 初始化后立即检查一次正式 GitHub Release，后台运行期间沿用现有五分钟检查与退避策略。
2. 发现新版本时，同一更新状态同时驱动托盘提醒、齿轮红点、主面板通知条和“关于与更新”页面。
3. 点击通知条“更新”直接打开“关于与更新”页面并开始现有的安全下载/校验流程；安装仍需用户确认。
4. 点击“稍后”后，本版本的主动弹出提醒静默 24 小时，通知条收起，但齿轮红点保留。
5. 有更新时点击齿轮，直接进入“关于与更新”；没有更新时仍进入普通设置首页。
6. 更新安装成功或远端不再高于本机版本时，通知条、红点和待提醒状态全部清除。
7. 普通 Git 提交不会触发客户端更新。维护者必须发布版本号更高的正式 GitHub Release，并附带固定名称 `HuahaiClipboard-Setup.exe`，客户端才会提示。

## 状态与边界

- 不新增服务器、账号、遥测或剪贴板数据上传。
- Windows 通知被禁用时，主面板通知条和齿轮红点仍正常工作。
- 离线、GitHub 限流或检查失败时不阻塞主面板，不重复弹错误；沿用现有退避和 Release 页面降级路径。
- 下载或校验失败时保留旧版本，更新条继续可见并在“关于与更新”显示失败原因。
- 通知条不得覆盖搜索框、筛选按钮或剪贴记录，也不得改变面板外框尺寸。

## 验收标准

- 更新可用时，主面板齿轮红点可见，通知条无需进入设置即可看见。
- 通知条没有左侧图标，在 80%、100%、160% 缩放下文字和两个按钮均不重叠。
- 通知条背景比原方案更通透，但标题、副标题和按钮文本保持清楚。
- 点击“稍后”收起通知条并保留红点；点击齿轮可直接进入更新页面。
- 缩小按钮显示放大的圆头粗横线，单击后程序继续在后台运行且可再次唤出。
- 现有更新检查、安装校验、复制、置顶、收藏、拖动、缩放及后台唤出测试继续通过。
