# 面板复制防回流、面板外隐藏与后台实时同步设计

## 目标

本次迭代修复三个相互关联的主流程问题：

1. 用户从花海剪贴板面板点击复制时，系统剪贴板更新事件不得再次生成历史记录。
2. 增加“点击面板外自动隐藏”设置，默认开启、可关闭并持久化。
3. 面板隐藏期间连续复制多条内容后，下一次唤出必须在首个可见帧显示最新历史，不显示旧列表或加载过程。

正式 UI 继续以 `src/HuahaiClipboard.App/Assets/Web/product-shell.html` 为唯一母版；本次只增加一个设置行和必要的状态绑定，不改变已确认的字体、狐狸图标、玻璃材质、列表、缩放、花瓣或按钮语言。

## 已确认的产品行为

### 面板内复制

- 文本、链接、图片和文件均适用。
- 复制成功后，原历史记录的位置、`LastCopiedAt`、收藏和置顶状态完全不变。
- 不创建新记录，也不把原记录移动到顶部。
- 复制失败时不留下抑制状态，后续真实复制仍能被捕获。
- 已经存在的重复记录本次不自动合并或删除，避免未经确认的数据变更。

### 点击面板外自动隐藏

- 设置路径：设置 → 系统 → 点击面板外自动隐藏。
- 默认值：开启。
- 点击其他程序、桌面或任务栏导致窗口失去激活时隐藏面板。
- 设置页属于同一个面板，页内点击不隐藏。
- 拖动或缩放正在进行时不因短暂失焦误隐藏。
- 关闭设置后，面板失焦仍保持显示。
- 隐藏动作继续遵循“后台运行”设置；默认只隐藏并在托盘保持运行。

### 后台实时同步

- 后台捕获和持久化仍然立即发生。
- 多个快速历史变更合并为“最新状态优先”的刷新，不能形成完整列表消息队列。
- 面板隐藏时不向已挂起的 WebView2 连续发送完整状态。
- 唤出时先恢复 WebView2、等待所有已登记的历史刷新、将最新状态同步到 DOM，完成后才显示窗口。
- 用户首个可见帧中的条数、排序和内容必须是唤出前已完成捕获的最新状态。
- WebView2 挂起策略保留，避免用持续高内存换取表面上的即时性。

## 技术设计

### 自写来源协议

每次面板写入系统剪贴板时，在同一个 Windows `DataObject` 中附加花海剪贴板私有格式和随机进程令牌。写入完成后记录 Windows 剪贴板序列号。捕获端只有在“私有令牌匹配”且“序列号等于本进程最近一次写入”时才忽略事件。

双条件避免两类误判：单纯时间窗口会吞掉用户紧接着进行的真实复制；单纯私有格式会误判某些完整重放剪贴板格式的第三方工具。外部复制产生新序列号或不含当前随机令牌，继续正常入库。

### 最新状态刷新协调器

使用单执行者、版本递增的异步刷新协调器：每次历史变更增加请求版本；同一时刻最多运行一个刷新；刷新执行期间出现的新请求会触发下一轮，但中间冗余请求不逐条执行。`FlushAsync` 等待调用时已登记的最新版本完成。

窗口隐藏时协调器只刷新内存模型；窗口可见时才发布 Web 状态。唤出路径调用 `FlushAsync`，再通过可等待的脚本调用将完整状态直接应用到 DOM，最后显示窗口。

### 窗口生命周期

`TransientWindowVisibilityController` 增加异步显示顺序：

1. 恢复 WebView2 内容活动；
2. 执行调用方提供的“显示前同步”；
3. 设置 Topmost；
4. 显示窗口。

失焦隐藏通过同一控制器执行，以保持 Topmost、隐藏和 WebView2 挂起顺序一致。

## 状态与持久化

- 权威历史：`JsonClipboardHistorySource`。
- 面板内存投影：`PanelViewModel.AllRecords`。
- Web DOM：可重建的显示投影，不是历史权威。
- 设置权威：`BehaviorSettings.HideOnOutsideClick`，缺失旧字段时按 `true` 迁移。
- 自写令牌：仅进程内随机值，不持久化、不上传 Git、不写入历史。
- 剪贴板序列号：仅进程内瞬时状态。

## 安全与活性义务

- `CG-1`：面板写入产生的更新永不进入历史。
- `CG-2`：外部应用随后复制相同或不同内容仍能进入历史。
- `CG-3`：写入失败不会污染后续来源判断。
- `OH-1`：开关默认开启且重启后保持用户选择。
- `OH-2`：关闭开关时失焦不隐藏；拖动或缩放期间不误隐藏。
- `LS-1`：后台快速连续变更不会并发刷新或无限积压。
- `LS-2`：唤出显示动作发生在最新历史应用到 DOM 之后。
- `LS-3`：隐藏时 WebView2 仍可挂起，内存优化不被回退。

## 错误处理

- 系统剪贴板被占用时沿用最多五次递增重试；只有成功写入后才记录自写序列号。
- 历史刷新失败时保留上一次有效列表并通过现有错误通道记录；后续请求允许重试，不永久卡死协调器。
- 显示前同步失败时不得无限等待；记录错误并使用最后一次有效状态显示，保证用户仍能关闭或重试。

## 验收

1. 对文本、图片和文件执行面板复制来源协议测试，断言私有格式存在且匹配序列才被抑制。
2. 模拟面板自写事件，断言历史数量、记录 ID、时间、收藏和置顶均不变化。
3. 模拟外部事件，断言正常新增或按现有规则去重。
4. 保存并重新加载设置，断言默认开启和关闭后的持久化。
5. 模拟失焦、关闭开关、拖动和缩放状态，断言隐藏决策正确。
6. 在刷新被人为阻塞时连续请求至少十次，断言无并发执行、最终版本完成且 `FlushAsync` 等待最新状态。
7. 模拟隐藏期间连续十条复制后唤出，断言主机动作严格为“恢复内容 → 应用最新状态 → Topmost → Show”，首帧条数为十条。
8. 浏览器真实点击设置开关、面板外区域和记录行，要求无控制台错误、原 UI 未漂移。
9. 完整运行 Core、App Windows 集成测试、托盘测试、Web 交互测试和 Release x64 构建。
